# CF Enhance · Codeforces 增强

融入 Codeforces 原网页的 Chrome 扩展，配合可选的 VS Code 插件，完成随机跳题、组题训练、本地测试、样例同步和提交反馈。

**只用网页功能，安装 Chrome 扩展即可；在 VS Code 本地测试也可以离线使用。同步网页样例和向 CF 提交代码时，才需要连接两端。**

[下载最新版本](https://github.com/Miaooo0O/cf-enhance/releases/latest) · [安装](#安装) · [首次连接](#connect) · [日常使用](#日常使用) · [常见问题](#常见问题)

## 下载与准备

当前配套版本：**Chrome 3.5.0 + Companion 0.7.0**。请同时更新两端，以使用按所选题目自动获取样例的功能。

| 文件 | 用途 |
| --- | --- |
| [cf-enhance-3.5.0.zip](https://github.com/Miaooo0O/cf-enhance/releases/download/v3.5.0/cf-enhance-3.5.0.zip) | Chrome 扩展，解压后加载 |
| [cf-enhance-companion-0.7.0.vsix](https://github.com/Miaooo0O/cf-enhance/releases/download/v3.5.0/cf-enhance-companion-0.7.0.vsix) | VS Code 插件，通过“从 VSIX 安装”安装 |

在 Release 页下载上表中的安装包；`Source code (zip)` 是开发源码，首次安装推荐使用命名好的扩展 ZIP 和 VSIX。

- 使用网页功能需要 Chrome，并能正常打开 [Codeforces](https://codeforces.com/)。
- 本地测试支持 C++、C、Python，需要自行准备对应编译器或解释器。默认程序名为 `g++`、`gcc`、`python`；C++ 使用 C++23，C 使用 C17。
- 本地测试不需要 CPH，运行插件不需要 Node.js、npm、GitHub Token 或 Codeforces API Key。
- 提交代码需要在 Chrome 中正常登录 CF。填写的 **handle 是 CF 用户名**，用于读取公开做题记录，不是密码。

## 安装

### 1. 安装 Chrome 扩展

1. 下载 `cf-enhance-3.5.0.zip`，解压到一个长期保留的文件夹。
2. Chrome 地址栏输入 `chrome://extensions/`，打开右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择直接包含 `manifest.json` 的文件夹。
4. 在 Chrome 右上角的扩展菜单中找到 **CF Enhance**，建议固定到工具栏，方便打开配对弹窗。
5. 打开或刷新一个 CF 页面。网页中应出现“随机跳题”“刷题记录”“显示设置”，顶部 Help 后出现“题单”和“中文”入口。

不要删除刚才解压的文件夹：Chrome 后续仍需从该目录读取扩展。本项目尚未上架 Chrome 应用商店。

### 2. 安装 VS Code 插件（可选）

1. 下载 `cf-enhance-companion-0.7.0.vsix`。
2. 打开 VS Code，进入左侧**扩展**页，点击该页右上角的 **… → 从 VSIX 安装…**，选择下载的文件。
3. 按提示重新加载 VS Code 窗口。
4. 打开一个代码文件夹，并确认信任该工作区，再打开代码文件。
5. 点击左侧 **CF Enhance** 图标，展开**测试与提交**。顶部应显示当前代码文件，以及“运行”“提交”按钮。

找不到入口时，可在命令面板搜索 **CF Enhance: 打开测试与提交面板**。

### 3. 设置编译器

点击测试面板工具栏的 **⚙**。若编译器不在 PATH 中，将以下设置改为本机程序的完整路径：

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `cfEnhance.compiler` | `g++` | C++ 编译器，需要支持 C++23 |
| `cfEnhance.cCompiler` | `gcc` | C 编译器 |
| `cfEnhance.python` | `python` | Python 解释器 |
| `cfEnhance.testTimeout` | `3000` | 普通用例时限，单位毫秒 |
| `cfEnhance.interactiveTimeout` | `120000` | 手动交互会话总时限，包含等待回复时间 |

程序路径只填写可执行文件，不附加命令参数。只使用网页功能时，不需要安装编译器。

## 首次连接：Chrome ↔ VS Code

**先打开 VS Code 插件，再在 Chrome 中完成配对。连接只在本机进行，不需要注册新账号。**

1. 在 VS Code 的“测试与提交”面板，点击**右上角“本地模式”**。连接设置默认收起，需要点击后才能看到配对按钮。
2. 点击**复制配对码**。也可在命令面板执行 **CF Enhance: 配对浏览器**。
3. 切到 Chrome，点击工具栏中的 **CF Enhance 扩展图标**，打开扩展弹窗。
4. 展开弹窗中的 **VS Code 联动（可选）**，将刚才复制的内容粘贴到“一次性配对码”输入框。
5. 点击**连接 VS Code**。浏览器若询问是否允许访问本机服务，请允许连接 `127.0.0.1`。
6. 保持至少一个 CF 页面打开，打开任意题目页并等待几秒。VS Code 面板右上角变为**网页已连接**，默认跟随模式下，选题框应出现网页当前题号。

配对成功后，凭据会保存在本机，平时无需每次粘贴。一次性配对码 **5 分钟有效且只能用一次**，过期或已使用时重新复制即可。

本机端口自动分配，不需要手动填端口或配置公网服务。使用多个 VS Code 窗口时，应从你实际写代码的窗口复制配对码；Chrome 当前连接到哪一个窗口，就将样例和反馈发给哪一个窗口。

> 第一次确认连接时，可以只打开题目、查看题号和样例是否同步，无需提交代码。

## 日常使用

### 从看题到测试

1. 在 Chrome 打开一道 CF 题目，在 VS Code 打开要使用的代码文件。文件可以叫 `1.cpp` 或其他名字，不要求题号命名。
2. 确认顶部的**代码文件、目标题目、提交语言**。
3. 题目样例会自动导入；点击 **⇩** 可重新获取。也可以选择训练场次中的题目，或输入题号 / CF 链接，插件会通过已连接的 Chrome 获取该题样例。
4. 点击 **▶ 运行**测试启用的用例；每个用例标题栏的 **▶** 只运行该例。
5. 运行状态和耗时显示在标题栏，程序输出显示在独立边框中。**这里的 AC 只表示通过本地用例，不是 CF 官方判题结果。**

代码来源可以选择当前编辑器、选中代码或其他文件。运行和提交读取当次代码快照，包含未保存的修改，不覆盖源文件。为了长期保存用例关联，建议先将代码保存到固定文件。

### 切题与样例保存

- **⇄ 跟随网页**：跟随 Chrome 当前题目；**⌖ 固定题目**：保留你选中的题目。点击选题框旁的按钮切换模式，悬停可看说明。
- **在上方选题框手动切题后，下方样例和当前提交结果一起切换，并自动固定该题**，不会被之后的网页切题覆盖。
- 用例按**文件＋题目**分别保存。同一个 `1.cpp` 做 A、B 两题时，各题拥有各自的样例、自定义输入和折叠状态，切回来仍可继续。
- 获取失败会显示原因，可用 **⇩** 重试；正在获取另一题时，不会拿上一题的样例充数。
- 编辑过的样例和手写用例会保留，删除过的样例不会被自动同步重新加回。

### 自定义测试与工具栏

| 按钮 / 操作 | 作用 |
| --- | --- |
| **＋** | 添加用例，直接进入输入框 |
| **⇩** | 重新获取当前所选题目的网页样例 |
| **⊟ / ⊞** | 折叠 / 展开全部用例；每例也可单独折叠 |
| **⇆** | 打开独立的手动交互测试窗口 |
| **⚙** | 打开插件设置 |
| **≡** | 打开完整运行日志 |
| 用例标题栏 **▶ / × / ⧉** | 单例运行 / 删除 / 复制输出，收起时也能操作 |
| **撤销删除** | 恢复最近删除的用例及其位置 |
| 输入框内 **Ctrl+Enter** | 运行当前用例 |
| 输入框内 **Ctrl+Shift+Enter** | 运行全部启用的用例 |

左侧编辑输入，右侧编辑答案。手写答案留空时只运行、查看输出；填写答案后自动比较。默认忽略空白分隔方式差异，`1` 和 `1.0` 仍视为不同；可在设置中选择 `exact` 比较方式。

### 提交到 Codeforces

1. 确保 Chrome 已登录 CF、VS Code 显示**网页已连接**。提交使用 Chrome 实际登录的账号，填写 handle 不会替你切换登录账号。
2. 核对代码来源、目标题号和语言，点击 **↑ 提交**。
3. Chrome 会在后台准备原生提交表单并自动提交，通常无需再去网页点 Submit。
4. 等待面板中该题的任务依次显示提交进度、CF 编号和最终 AC / WA / TLE 等结果。其他题目的旧记录位于折叠的**提交历史**中。

网页手动提交的本人记录也可同步到 VS Code。如果无法唯一确认本次提交，可在 CF 结果页的对应记录旁点击“关联 VS Code”。登录失效、验证码、限流或表单错误需要在网页处理，插件不会自动重复发送代码。遇到编号迟迟不返回时，先点**查看网页**检查是否已经提交成功。

本地测试支持 C/C++/Python；提交菜单还可选择 CF 支持的 Java、Rust 等语言，这不代表这些语言已支持本地运行。

### 手动测试交互题

1. 打开交互题代码，点击用例工具栏 **⇆**。
2. 在新窗口点击**开始**。程序的询问会实时出现在带边框的通信区域中。
3. **你扮演交互器**：在下方输入回复，点“发送”或按 **Ctrl+Enter**。可选择是否追加换行。
4. 可发送 **EOF** 关闭输入、停止程序、重新开始，或复制通信记录。关闭窗口会停止该窗口拥有的程序。

**←** 表示程序输出，**→** 表示你的回复。C++ 应使用 `endl` / `flush`，C 应使用 `fflush(stdout)` 刷新输出；Python 使用无缓冲模式运行。默认总时限 120 秒，可在设置中调整。

这是一种手动调试方式，不自带各题的官方交互器，也不会自动判断官方 AC。

## Chrome 网页增强

- **随机跳题**：按评分区间、标签、全部 / 任一标签匹配抽题；支持避免重复、排除已 AC 或尝试过的题。需要排除做过的题时，先填写 handle 并同步公开提交记录。
- **刷题记录**：查看抽题历史，按题号、题名、状态、评分、标签、日期筛选。“重置去重记录”保留可查看的历史日志。
- **题单**：从顶部 Help 后进入，创建独立训练场次；可混合设置不同评分、标签和题数，自由选题，查看本场已看 / 尝试 / AC 状态，支持删除与恢复。每场最多 50 题、12 组条件。
- **AC 后继续**：提供“随机跳一题”和“比赛下一题 / 本场下一题”；题单按本场顺序跳过已 AC 题，普通入口按比赛顺序，随机入口优先随机。不会自动切走当前页面。
- **提交辅助**：从 problemset 题目页进入 Submit 时，自动带上对应题号。
- **显示设置**：独立隐藏标签、评分，收起侧栏、放大题面；顶部“中文”只翻译界面按钮、菜单和标签，不翻译题面、题名、样例或代码。

训练场次、看题记录、抽题记录保存在当前 Chrome 配置中；题单地址不是 CF 官方比赛，也不能直接分享给其他电脑读取本机数据。已 AC / 尝试状态来自所填写 handle 的公开提交记录；完整同步失败时保留之前的数据。同步超过一天后，使用账号排除前需重新同步。

## 更新

1. 从 [Latest Release](https://github.com/Miaooo0O/cf-enhance/releases/latest) 下载配套的 Chrome ZIP 和 VSIX。
2. Chrome 新文件**覆盖到原扩展目录**，打开 `chrome://extensions/`，对 CF Enhance 点击**重新加载**，再刷新已经打开的 CF 页面。沿用原目录和 Chrome 配置可保留记录。
3. VS Code 通过“从 VSIX 安装”安装新版，然后重新加载窗口。
4. 检查两端连接状态。通常无需重新配对；无法恢复时，在 VS Code 重新复制配对码，在 Chrome 再连接。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| VS Code 只有“本地模式”，找不到配对按钮 | 点击面板右上角的“本地模式”文字，连接设置才会展开。也可执行“CF Enhance: 配对浏览器”。 |
| 配对码无效或过期 | 在目标 VS Code 窗口重新复制，5 分钟内粘贴完整内容；已使用的码不能再次使用。 |
| 提示需要允许连接本机 VS Code | 在 Chrome 配对弹窗点击连接，允许访问 `127.0.0.1` 后重试。无需开放公网端口。 |
| 已连接，但题号 / 样例不更新 | 同时更新两端，重新加载 Chrome 扩展并刷新至少一个 CF 页面；打开题目页等几秒。检查是否处于固定模式，是否配对到了另一个 VS Code 窗口。 |
| 选了题目但没有样例 | 先确认 CF 题目在 Chrome 能正常打开，再用 ⇩ 重试；登录 / 验证页或网络错误会阻止读取。手动交互题也可能没有适合普通测试的样例。 |
| 编译器找不到、无法运行 | 点 ⚙ 检查对应程序路径；C++ 编译器需要支持 C++23。Python 需要指向实际解释器。 |
| 切题后找不到以前的自定义输入 | 切回原题并打开原代码文件。用例按“文件＋题目”区分，换文件、另存为或换工作区不会自动迁移关联。 |
| 显示 `Extension context invalidated` | 更新后旧 CF 页面仍使用旧连接，刷新该页面即可；不要为此清空扩展存储。 |
| 一直等待提交编号 | 点“查看网页”确认登录、验证码、限流及表单状态；如已经提交成功，不要重复发送，可从对应结果行关联任务。 |
| 交互程序没有输出 | 确认已点开始，检查代码是否在等待首条输入，以及是否主动刷新了输出缓冲区。 |
| 使用时需要 GitHub Token 吗？ | 不需要。普通下载、安装、配对和使用均不需要 GitHub Token 或 CF API Key。 |

## 数据与权限

基础权限为扩展存储、定时任务和 CF 域名访问；连接 VS Code 时额外申请本机 `127.0.0.1` 访问权限。本机服务只监听回环地址，端口自动分配，配对凭据保存在本机。不读取浏览历史、不上传遥测、不使用云端中转，不索取 CF 密码或 Cookie 的值。

点击提交后，所选代码快照会经本机连接交给浏览器并提交到 CF。提交历史不保存源码，任务完成或取消后释放待提交源码。本地测试以普通进程运行，不提供文件系统或内存隔离；编译器诊断可能包含出错行。

单组最多 50 个用例，单项输入 / 答案最多 64 KiB，总用例存储上限 12 MiB。普通进程输出上限 1 MiB；面板预览前 16000 字符，完整内容可在日志查看。交互通信记录上限 1 MiB。
